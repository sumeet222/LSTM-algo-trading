# Package009 WF2 replication interfaces

This candidate-only extension retains the existing neural engine and D6g calibration/fresh-refit loop. It admits exactly TM0 then MC0, seed42, December-2023 fitting and January–June2024 development evaluation. It does not authorize future fits or confirmation access.

`lstm_data.wf2_replication` exposes `--prepare`, `--dry-run`, `--status`, `--plan`, `--approval` and `--output`. Preparation creates a new packet and independently recomputes inner/full stock and market recipes. Neural execution requires an absolute output path, e.g. `--output "$PWD/reports/data_audit/<packet>"` from the repository root; the worker derives project-relative artifact references from that root. The final plan binds actual view identities, the two concrete contracts, source/clock/protocol references, prior four consumed pairs and linked registry v3. A valid actual human response must match the plan SHA and both exact run IDs. The module entry delegates to its canonical imported main to preserve exact authority class identity under `python -m`.

`WF2PairAuthority` is a sealed concrete authority. `ensure(activity, input_id)` verifies source, recipe, code, approval, historical journals and current-pointer coherence. `view(key)` checks exact approved view and preprocessing IDs for `inner`, `validation`, `refit` or `WF2`. It admits no arbitrary subclass or duck-typed permission. `append(status, detail)` records the existing STARTED→CALIBRATED→REFITTING→COMPLETED lifecycle, or FAILED; STARTED consumes a slot even on failure. No duplicate ID, reordered queue, overlapping pair or cap expansion is allowed. The parent supervisor refuses a replay once a real new pair has started and checks remaining package time before the next pair.

`BatchInputs.fold` defaults to `WF1`. Explicit `WF2` selects the December fitting boundary and WF2 evaluation view while retaining existing indexed batches, mask rules and stock/market join calculation. There is no duplicated raw archive or dense per-seed feature cache.

`real_bridge_run.epoch_pass(..., batch_sink=None)` keeps the original numerical loop. If supplied, the sink observes detached session losses and the return from the single existing global clip, after the original optimizer step. `BatchTelemetry(path, run_id, architecture, stage).record(epoch, batch_index, batch, loss, preclip_norm)` writes version `TA009_BATCH_OBSERVER_v1` scalar CSV rows only. It draws no RNG, computes no additional backward pass and modifies no optimizer/gradient state. The deterministic fabricated one-batch test compares parameters, all optimizer tensors and Torch RNG bitwise with observation on/off. The clipping multiplier follows `min(1, 1/(norm+1e-6))`; historical G6's cap-exceedance measure remains `norm>1`.

`lstm_data.wf2_review --package PATH [--plan PATH --approval PATH]` performs final-weight CPU inference and matched-panel/telemetry verification without fitting or journal mutation. It checks target/key equality, full forecast replay tolerance 2e-6, exactly one row per actual optimizer step, every session once per epoch, batch-to-epoch MSE reconstruction and clipping fractions. CSVs provide exact five-stock forecasts, ZERO, daily/monthly paired differences, loss concentration and batch loss/target-tail/norm associations. Five-session paired block summaries reuse the existing deterministic utility and remain exploratory, without full G8 selection correction.
