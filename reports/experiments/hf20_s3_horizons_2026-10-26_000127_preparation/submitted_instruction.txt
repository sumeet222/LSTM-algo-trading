1.2 Horizon ranking labels, true target operands, and transforms
At the same origin, rank the 20 legitimate future returns descending (higher return = better). The primary label for an NR rank model is
\[
q^{(h)}_{i,t}=2\frac{r^{(h)}_{i,t}-1}{19}-1,
\]
where \(r^{(h)}\in[1,20]\) is the ascending average/midrank of future returns (so rank 20 means best), with the existing tie convention. Its optimized loss is the same session/origin/stock-weighted \(\mathrm{MSE}(s,q^{(h)})\) as S2 NR. NR score outputs do not represent returns.

For the h-specific T2R comparator, create an explicitly versioned TG20_h target:
\[
\begin{aligned}
 m_t^{(h)}&=\operatorname{median}_{i\in20}R^{(h)}_{i,t},\\
 D_t^{(h)}&=\operatorname{median}_{i\in20}|R^{(h)}_{i,t}-m_t^{(h)}|,\\
 Y^{(h)}_{i,t}&=\frac{R^{(h)}_{i,t}-m_t^{(h)}}{D_t^{(h)}+\epsilon_{h,\mathrm{fit}}},\\
 Z^{(h)}_{i,t}&=\operatorname{asinh}\!\left(Y^{(h)}_{i,t}/s_{h,\mathrm{fit}}\right).
\end{aligned}
\]
Fit \(\epsilon_{h,\mathrm{fit}}\) and \(s_{h,\mathrm{fit}}\) separately per horizon/fold/phase on permitted history, using the exact current P020 fitting rule, not newly guessed quantiles, a reused four-hour floor, an outer-year distribution or selected 2025 outcomes. At h=4 use the unaltered stored P020 recipe; compare the original TG20 to an independently reconstructed h=4 witness. As with S1/S2 T2R, squared \((\hat Z-Z)^2\) is the actual optimized objective, and a once-only \(s\sinh\hat Z\) inverse is diagnostic context in original TG20_h units, not the conditional expected raw return. Output ordering may be obtained directly from \(\hat Z\).

Do not divide realized each-stock return by its own predicted volatility for ranking: this would silently change the object being ordered. Origin-shared median/MAD/asinh are order preserving but yield different regression objectives across h. Report performance in ranking metrics on the appropriate raw return rather than comparing h-specific z-MSE levels across horizons as though they were the same risk.

2.2 S3-B: only replace M2 with a horizon-aligned historical return feature
Why M2 specifically? Current M2 is the one FT16 channel that directly computes historical four-hour origin-matched outcomes. M1 is an already observed one-hour price-move indicator; M3/M4 are intentionally long daily contexts; V1/V2 estimate historical volatility; T3/T4 and other channels are not automatically “wrong” because the label horizon changes. Blindly replacing every lookback or multiplying volatility by \(\sqrt h\) would confound the experiment.

Define for each historical feature step \(s\) a new M2_h by taking the exact existing P020 M2 calculation and replacing only its underlying strictly previously observed and matured origin-matched four-hour log-return histories with h-hour histories of the same source-price convention. Preserve original M2's same-origin-type historical indexing, denominators, count requirements, floor/fallback behavior, missingness semantics and historical-as-of construction. In the currently understood recipe, it has the form
\[
\operatorname{M2}^{(h)}_{i,s}
\;\sim\;
\frac{\operatorname{mean}(\text{up to 20 preceding valid origin-matched }R_i^{(h)})}
{\operatorname{RMS}(\text{up to 60 preceding valid origin-matched }R_i^{(h)})},
\]
with the original 19/20 and 57/60, maximum-run/floor and own-source-availability rules if those are indeed the live P020 rules. The symbol \(\sim\) is intentional: inspect and implement the live P020 exact algebra and scaling, not this schematic formula as a replacement specification. The source of M2 must not include today's future h-hour outcome, even in any of the 48 historical feature steps. All underlying outcomes must mature by that particular step's information cutoff; a mere global train/test split is insufficient. Historical M2 for a forecast origin is not a currently unknown future label.

For h=1 and 2, fit the same P020 robust M2 scaling/floor recipe using only permitted inner-train or refit inputs for that fold/phase (and any original permitted fallback rules); record phase-dependent parameters. No new cross-stock scaler, no target-scale leakage, no input clipping or learned imputer. All other 15 FT16 channels, their values and source/phase recipes must be unchanged bit-for-bit on matched keys. The new input remains 48×16; LSTM width, architecture/parameter count, optimizer, lookback and stock set remain unchanged.

At h=4, reconstructed \(\operatorname{M2}^{(4)}\) must match the original P020 M2 including input-clock and phase scaling/fallback (bitwise on stored float32 inputs where feasible; otherwise exact frozen numerical tolerances with explained roundoff). Consequently S3-B h=4 is an identity control with no new training. If this fails, the B-stage feature construction has not been verified: do not launch B training. Do not alter P020 or the earlier models to make identity pass.

For h=1,2 and F21–F24, train both matched LSTM objectives NR and T2R against their S3-A counterparts at the same horizon, source-key population and fold. This is a deliberate decision to test the effect under both a pure-ranking loss and the historical transformed-return loss; it prevents overinterpreting a change seen only for one objective. Do not decide which objective/horizon to run based on S3-A OOS performance. Keep S3-B free of extra channels, altered M1 lookbacks, sector/market context, minute inputs, alternative nonlinear cells and 1h/2h/4h feature-grid optimization.

New S3-B neural lifecycles: \(2\text{ shorter horizons}\times4\text{ folds}\times2\text{ neural objectives}=\boxed{16}\). Archived h4 inputs/models are the identity control.

Scientific limitation: M2_h may expose different historical outcomes, not merely a feature scaling adjustment; a positive B effect establishes value of this specific horizon-aligned historical feature construction, not a universal best lookback, trading alpha, or extra recurrent capacity. The other 15 channels still include longer-term context deliberately.
